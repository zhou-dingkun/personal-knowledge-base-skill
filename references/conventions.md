# 知识库细则（Conventions）

> `SKILL.md` 的完整展开。AI 在需要判断"这条该放哪、怎么命名、要不要更新索引"时读这里。

## 1. 分区职责与边界

| 目录 | 放什么 | 不放什么 | 生命周期 |
|---|---|---|---|
| `01-收件箱` | 临时剪藏、随手笔记、灵感、待办、刚收到的文件 | 整理好的东西 | 定期清空；归位后删原文 |
| `02-资料库` | 原始材料：证书、PDF、扫描件、照片、表格 | 自己写的笔记 | **只增不改** |
| `03-笔记` | 自己整理的知识、结论、方法、复盘 | 原始文件 | 长期维护、持续更新 |
| `04-项目` | 有明确目标与结束条件的事 | 日常记录 | 完成后归档 |
| `05-作业` | 课程作业（一作业一文件夹） | 通用知识 | 保留为记录 |
| `06-Agent工具` | 本机工具脚本、用法说明、环境说明 | 笔记 | 工具文档 |
| `00-模板` | 笔记 / 作业模板 | 正式内容 | 只读参考 |

**判定顺序**：是别人/机构给的原始文件？→ `02-资料库`。是自己想清楚写下来的？→ `03-笔记`。
是正在进行、有截止日期的？→ `04-项目`（课程作业 → `05-作业`）。拿不准 → 先扔 `01-收件箱`。

## 2. Frontmatter

必填四项，缺一不可：

```yaml
---
type: note            # note | certificate | document | project | inbox | assignment | person
title: 人类可读标题
tags: [学业, 科研]      # 受控词表，新增须在 INDEX.md 登记
created: YYYY-MM-DD
updated: YYYY-MM-DD    # 每次修改必须更新
status: 活跃            # 收件箱 | 整理中 | 活跃 | 已完成 | 归档
---
```

分类型的补充字段：

| type | 建议补充字段 |
|---|---|
| `certificate` | `source`（颁发机构）、`date`（颁发/生效日期）、`expires`（有效期至） |
| `document` | `source`、`path`（原件路径） |
| `project` | `deadline`、`status`（规划中 / 进行中 / 已完成 / 已归档） |
| `assignment` | `course`、`deadline`、`assigned`、`score` |
| `person` | `relation`、`contact`（联系方式一律脱敏） |

## 3. 命名

| 类别 | 规则 | 例 |
|---|---|---|
| 笔记 | `YYYYMMDD-简短描述.md` | `20260828-大气透过率研究入门.md` |
| 资料 | `主题-描述.ext` | `202608-助研费凭证.pdf` |
| 证书 | `颁发年月-证书名称.ext` | `202603-普通话二级乙等证书.pdf` |
| 作业目录 | `YYYYMMDD-课程名-作业名` | `20260901-高等数学-第一章习题` |
| 项目目录 | `项目名` | `毕业设计` |

**禁止**：空格、引号、`\ / : * ? " < > |`。中文可用，但同一目录内风格保持一致。

## 4. 标签（受控词表）

初始词表（按需增补，**新增必须在 `INDEX.md` 登记**）：

`学业` `科研` `证书` `技能` `编程` `生活` `健康` `财务` `项目` `灵感` `待办`

原则：标签是**跨笔记的检索维度**，不要当分类用；一张笔记 2–4 个标签为宜。

## 5. 索引（INDEX.md）

`INDEX.md` 是**活索引**，由人和 AI 共同维护：

- 新增 / 移动 / 归档笔记 → 更新对应章节
- 章节按区组织（`02-资料库` / `03-笔记` / `04-项目` / `05-作业` / `06-Agent工具` / `01-收件箱`）
- 条目格式：`- [显示名](相对路径) — 一句话说明`
- 标签词表变更也登记在文末

`01-收件箱` 的内容**不写入正式索引**（它还没被整理）。

## 6. 资料文件与索引笔记

每个入库的原始文件都要有一个同名或同组的 `.md` 索引笔记：

```
02-资料库/奖项与荣誉/
├── 202608-助研费凭证.pdf
└── 202608-助研费凭证.md     ← 索引笔记
```

索引笔记必须写清五件事：**是什么 / 时间 / 来源 / 用途 / 存储路径**。

为什么强制：AI 读 Markdown 的成本远低于解析 PDF 或图片；而且写索引的过程本身会逼你把"这到底是什么"想清楚。

> 扫描件（无文字层）通常解析不出文本；此时先渲染成图片再识读，或手工补全索引要点。

## 7. 工作流

### 7.1 收件箱归位
1. 逐项判断去向（见 §1）
2. 原始材料 → `02-资料库/<主题>/` + 写索引笔记
3. 知识 → `03-笔记/<主题>/`（用 `00-模板/笔记模板.md` 起头）
4. 项目 / 作业 → 建对应目录
5. **删除收件箱原文**
6. 更新 `INDEX.md`

### 7.2 新建笔记
复制 `00-模板/笔记模板.md` → 填 frontmatter → 写内容 → 更新 `INDEX.md`。

### 7.3 作业协作（`05-作业`）
**每个作业一个文件夹**：

```
05-作业/20260901-高等数学-第一章习题/
├── README.md      # 课程 / 布置日期 / 截止日期 / status / 评分（必填）
├── 题目/          # 题目.pdf、题目.md、截图
├── 解答.md        # AI 作答（必填）
├── 过程/          # 草稿、推导（可选）
└── 附件/          # 数据、代码（可选）
```

流程：读题 → **检索知识库**（`03-笔记` / `02-资料库`）→ 写入 `解答.md` →
更新 `README.md` 的 `status` → 可复用知识点提炼回 `03-笔记/` 并互链 → 登记 `INDEX.md`。

作答纪律：**标注来源**（相对路径）、**不编造**（不确定写 `> 待确认：…`）、保留推导过程。

### 7.4 每次修改后
- 更新 frontmatter 的 `updated`
- 结构变化同步 `INDEX.md`

## 8. Git

- 约定式提交信息：`feat:` `fix:` `docs:` `chore:` `refactor:`
- 一个逻辑变更一个提交
- 提交前 `git status` 确认没有敏感文件
- 推荐：`git init` + 私有远端 + 定期 push（"本地一份 + 云端一份"）

## 9. 隐私分级

**可入库**：一般笔记、公开可查的荣誉、模板、工具文档。

**敏感**（证件照、身份证、含他人姓名/学号/编号的材料、账号密钥、住址电话）：

- 不进公开仓库、不外发
- 需要版本管理时：用**私有**仓库，或把对应目录写进 `.gitignore`
- 文档里引用一律 `<已脱敏>`
- AI 准备输出敏感内容前必须提醒用户

> 建议在知识库创建之初就决定敏感目录的归属（入库 / 忽略），中途改变会涉及 Git 历史清理。

## 10. AI 行为红线

- ❌ 不编造事实、数据、引用；不确定就标 `> 待确认：…`
- ❌ 不覆盖原始文件；不删除用户的原始材料
- ❌ 不把 `01-收件箱` 当长期仓库；不在区根目录堆文件
- ✅ 引用知识库内容时给出相对路径来源
- ✅ 改动后更新 `updated` 与 `INDEX.md`
