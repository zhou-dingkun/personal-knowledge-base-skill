# 个人知识库 — AI 工作指令

> 本文件是知识库的「宪法」。DSH / Claude Code / Cursor / Copilot / Codex / Cline 等 AI 工具在会话开始时**自动加载**。
> 各子目录另有 `AGENTS.md`，在处理该目录内容时自动加载，且**优先级更高**。

## 1. 这是什么

- 形态：纯 Markdown 文本 + 原始文件（PDF / 图片），Git 版本管理
- 内容：个人资料、证书、学业、研究、技能、生活记录，**默认不对外共享**
- 目标：可长期演进、可被任何 AI 工具读写、零厂商锁定

### 1.1 AI 工具兼容性（读与写）

- 本库规范对主流 AI 工具**通用**：DSH、Claude Code、Cursor、GitHub Copilot、Codex、Cline、Windsurf 等
- 兼容入口：`CLAUDE.md`、`.github/copilot-instructions.md`、`.cursor/rules/`、`.clinerules/` 均为指向本文件的指针，避免多份规范漂移
- 任何 AI 工具按本文件规则写入：新建笔记用 `00-模板/笔记模板.md`，修改后更新 frontmatter 的 `updated` 与 `INDEX.md`
- **唯一权威规范是本文件（AGENTS.md）**

## 2. 目录结构（四区 + 作业 + 工具 + 模板）

| 目录 | 用途 | 生命周期 |
|---|---|---|
| `01-收件箱` | 临时剪藏、随手笔记、灵感 | 定期清空归位 |
| `02-资料库` | 原始材料：证书 / PDF / 扫描件 / 图片，按主题分子目录 | 原始文件**只增不改** |
| `03-笔记` | 整理后的知识笔记，按主题分子目录 | 长期维护 |
| `04-项目` | 进行中的项目 / 课题 / 论文 | 完成后归档 |
| `05-作业` | AI 协助完成的作业，**每个作业一个文件夹** | 保留为记录 |
| `06-Agent工具` | 本机工具脚本、用法说明、环境说明 | 工具文档，长期维护 |
| `00-模板` | 笔记 / 作业模板 | 只读参考 |

流转模型：**收件箱 → 资料库 / 笔记 / 项目**。

## 3. 笔记规范（所有 Markdown 文件必须遵守）

### 3.1 Frontmatter（YAML 头部）

```yaml
---
type: note          # note | certificate | document | project | inbox | assignment | person
title: 笔记标题
tags: [学业, 证书]    # 受控词表，见 3.3
created: YYYY-MM-DD
updated: YYYY-MM-DD  # 每次修改必须更新
status: 活跃          # 收件箱 | 整理中 | 活跃 | 已完成 | 归档
---
```

### 3.2 命名

- 笔记类：`YYYYMMDD-简短描述.md`
- 资料类：`主题-描述.ext`
- 文件名避免空格、引号与 `\ / : * ? " < > |`

### 3.3 标签词表（受控，新增须在 INDEX.md 登记）

`学业` `科研` `证书` `技能` `编程` `生活` `健康` `财务` `项目` `灵感` `待办`

### 3.4 链接

- 内部链接优先用**相对路径**：`[标题](../03-笔记/学业研究/xxx.md)`
- Obsidian 的 `[[双链]]` 兼容但非权威形式

### 3.5 资料文件配套索引

每个入库的 PDF / 图片必须有**同名或同组的 `.md` 索引笔记**，写明：是什么、时间、来源、用途、存储路径。
**AI 优先读索引笔记，而不是直接解析二进制文件。**

## 4. 工作流（AI 执行规则）

### 4.1 收件箱清空
处理 `01-收件箱` 内容时：
1. 原始材料 → `02-资料库` 对应子目录 + 写索引笔记
2. 知识笔记 → `03-笔记` 按主题归类
3. 项目内容 → `04-项目`
4. 归位完成后**删除收件箱原文**，并在 `INDEX.md` 登记

### 4.2 新建笔记
用 `00-模板/笔记模板.md` 初始化 → 填 frontmatter → 更新 `INDEX.md`。

### 4.3 每次修改后
- 更新 frontmatter 的 `updated`
- 内容结构变化时同步更新 `INDEX.md`

### 4.4 作业（AI 依据知识库协助完成）
- **每个作业一个文件夹**：`05-作业/YYYYMMDD-课程名-作业名/`，完整规范见 `05-作业/AGENTS.md`
- 作答写入该文件夹的 `解答.md`，**标注知识库来源**、不编造，并同步更新 `README.md` 的 `status`
- 可复用知识点回灌到 `03-笔记/` 并互链

## 5. Git 规则

- 提交信息用**约定式提交**：`feat:` `fix:` `docs:` `chore:` `refactor:`
- 一个逻辑变更一个提交；提交前 `git status` 确认无敏感文件
- 禁止提交：密钥、密码、隐私证件照片、`AGENTS.local.md`
- 有远端时提交后 `git push`

## 6. 隐私与安全（红线）

- 本库可能含个人证件 / 证书，以及包含**他人**姓名 + 学号 + 编号的材料
- 敏感内容**绝不推送到公开仓库、绝不外发**，不向无关方透露他人信息
- 身份证号、手机号、银行账号等引用一律用占位符 `<已脱敏>`；AI 输出此类内容前必须提醒用户
- 需要纳管敏感材料时，用**私有**仓库，或把对应目录写入 `.gitignore`

## 7. 常用命令

```bash
git add -A
git status                 # 检查无敏感文件
git commit -m "docs: …"
git log --oneline -10
git push
```

## 8. 工具库与环境

本机可用的工具脚本、调用方法与环境清单统一放在 `06-Agent工具/`（该目录有独立 `AGENTS.md`，处理其中的内容时自动加载）：

| 文档 | 内容 |
|---|---|
| `06-Agent工具/环境说明.md` | 本机环境清单（Python / Node / 图像工具 / Git 等） |
| `06-Agent工具/工具用法.md` | 工具调用方法（PDF 文本提取、页面渲染、图像转换等） |
| `06-Agent工具/脚本/` | 可直接调用的脚本 |

原则：**能读 Markdown 就不解析二进制**；必须解析时，把结论沉淀成索引笔记，避免重复解析。
